# Даша | Заготовки и меню

Production-ready Telegram-бот закрытого кулинарного клуба: продажа доступа, платежи, подписки, персональные приглашения, напоминания, автоматическое удаление из группы и админ-инструменты.

## Возможности

- `/start`, адаптивное меню и опциональное фото/видео;
- тарифы вне handlers, оферта и политика перед оплатой;
- единый платежный слой с Mock и Robokassa;
- проверка подписи, суммы и invoice, идемпотентная обработка;
- продление от текущей даты окончания и бессрочный доступ;
- персональная invite-ссылка на одного участника;
- напоминания за 3 дня/1 день, окончание доступа и удаление из клуба;
- админка внутри Telegram: обзор, мини-CRM, бесплатные материалы с уникальными ссылками и черновики рассылок;
- Fastify health check, ResultURL и защищенный payment return flow;
- pretty-логи в development и JSON-логи в production.

## Стек

Node.js 20.19+, TypeScript, grammY, MongoDB/Mongoose, Fastify, Zod, Pino, node-cron, Vitest, ESLint, Prettier и PM2.

## Локальная установка

```bash
npm install
cp .env.example .env
npm run dev
```

## .env

Минимально заполните `BOT_TOKEN`, `MONGODB_URI`, `BOT_USERNAME` и `ADMIN_IDS`. Для выдачи доступа добавьте `PRIVATE_CLUB_CHAT_ID`. Значения Robokassa обязательны только при `PAYMENT_PROVIDER=robokassa`.

Если сервер не может подключиться к IP-адресу, который DNS возвращает для `api.telegram.org`, можно указать доступный IPv4 в `TELEGRAM_API_IP`. Это меняет маршрут только для Telegram-запросов данного процесса; TLS продолжает проверять имя `api.telegram.org`.

Цены в [src/config/products.ts](src/config/products.ts) являются явно помеченными placeholders — замените их реальными бизнес-значениями перед запуском продаж. Все суммы хранятся целым числом копеек.

## MongoDB

Подойдет локальная MongoDB или MongoDB Atlas:

```env
MONGODB_URI=mongodb://127.0.0.1:27017/dasha_bot
```

Для наиболее сильных транзакционных гарантий production MongoDB рекомендуется replica set. Критичная защита от двойного начисления дополнительно реализована атомарным claim по `processedAt`.

## Как создать Telegram bot

1. Откройте `@BotFather`, выполните `/newbot`.
2. Скопируйте токен в `BOT_TOKEN`.
3. Укажите username без `@` в `BOT_USERNAME`.
4. При необходимости настройте команды `/start` и `/admin` через `/setcommands`.

## Как добавить бота в закрытую группу

Добавьте бота администратором в приватную супергруппу, скопируйте ее numeric ID (обычно начинается с `-100`) в `PRIVATE_CLUB_CHAT_ID`.

## Какие права дать боту

Нужны права приглашать пользователей и блокировать/разблокировать участников. При запуске бот пытается проверить доступ к группе и выводит понятное предупреждение, если проверка невозможна.

## Robokassa (тестовый режим)

### Информация для проверки магазина

Заполните все поля в `src/config/legal.ts`: полные ФИО и ИНН самозанятого, контакты, оформление заказа и сроки, оплату, предоставление доступа, отказ от покупки, порядок и сроки возврата, обработку персональных данных. Эти сведения доступны в боте через кнопку «Информация и условия» в главном меню и на экране тарифа перед оплатой. Пустые поля на экране скрываются; заполните необходимые сведения и опубликуйте обновлённую версию бота до ответа поддержке Robokassa «Готово». Не указывайте удержание комиссии платёжного сервиса или банка из возврата.

Четыре PDF-файла для кнопок на этом экране хранятся локально в `assets/legal/` и исключены из Git. На VPS разместите их в отдельной постоянной папке и укажите её абсолютный путь в `LEGAL_DOCUMENTS_DIR` серверного `.env`. Имена файлов: `public-offer.pdf`, `license-agreement.pdf`, `privacy-policy.pdf`, `personal-data-consent.pdf`. Реквизиты и контакт задаются там же через `LEGAL_SELLER_NAME`, `LEGAL_SELLER_INN`, `LEGAL_BANK_DETAILS`, `LEGAL_CONTACTS`; эти значения не хранятся в публичном репозитории. Не храните PDF внутри `/opt/dasha-bot`: автодеплой заменяет эту папку целиком.

Заполните локальный `.env` и публичный HTTPS-адрес сервера. `.env` игнорируется Git.

```env
PAYMENT_PROVIDER=robokassa
PUBLIC_BASE_URL=https://YOUR_PUBLIC_HOST
ROBOKASSA_MERCHANT_LOGIN=
ROBOKASSA_TEST_MODE=true
ROBOKASSA_TEST_PASSWORD_1=
ROBOKASSA_TEST_PASSWORD_2=
ROBOKASSA_HASH_ALGORITHM=SHA256
```

В кабинете Robokassa выберите SHA256 и укажите:

- Result URL: `https://pay.dashamenu.ru/payments/robokassa/result`, POST;
- Success URL: `https://pay.dashamenu.ru/payments/robokassa/success`, GET;
- Fail URL: `https://pay.dashamenu.ru/payments/robokassa/fail`, GET.

Установите `PUBLIC_BASE_URL=https://pay.dashamenu.ru`. Для тестового режима нужны `ROBOKASSA_TEST_PASSWORD_1` и `ROBOKASSA_TEST_PASSWORD_2`; для реального — `ROBOKASSA_PASSWORD_1` и `ROBOKASSA_PASSWORD_2`. Храните их только в серверном `.env` с правами 600. MongoDB должна работать как replica set для атомарного подтверждения платежа и продления подписки.

ResultURL сверяет подпись Паролем №2, режим и сумму с заказом. Подтверждение платежа и продление подписки фиксируются в одной транзакции, после чего задача выдачи приглашения повторяется при сбоях Telegram. Повторное уведомление отвечает `OK{InvId}` без повторного продления. SuccessURL и FailURL показывают страницы возврата в бот и не подтверждают оплату. При тестовой оплате checkout подписывается тестовым Паролем №1 и содержит `IsTest=1`. Для реального режима нужны `ROBOKASSA_PASSWORD_1` и `ROBOKASSA_PASSWORD_2`.

Приглашение создаётся как заявка на вступление. Бот одобряет её только для Telegram ID с активной подпиской и соответствующей ссылкой, затем отзывает ссылку. Пересланная ссылка другому пользователю не даст доступ. После окончания подписки бот удаляет участника; ошибки Telegram повторяются при следующем запуске планировщика.

Для открытия продаж задайте в серверном `.env` `CHECKLIST_MODE=false`, `PRE_REGISTRATION=false` и `PUBLIC_PAYMENTS_ENABLED=true`. При `ROBOKASSA_TEST_MODE=true` кнопки тарифов ведут на тестовую оплату без списания. Для реальных платежей нужны рабочие `ROBOKASSA_PASSWORD_1` и `ROBOKASSA_PASSWORD_2` и `ROBOKASSA_TEST_MODE=false`. Первый доступ стоит 2 000 ₽ за 30 дней или 3 000 ₽ за 90 дней; последующее продление на 30 дней — 1 000 ₽. Перед реальной оплатой убедитесь, что магазин активирован, рабочие пароли сохранены в кабинете, юридические документы отражают фактические цены, а решение «Самозанятые ФНС / Робочеки СМЗ» активно. После платежа проверьте выдачу доступа и чек в «Мой налог».

## Проверка платежа

Кнопка «Проверить оплату» читает только серверный Payment. При `succeeded` вызывается единый идемпотентный success processor. Robokassa использует ResultURL как основной механизм подтверждения.

## Тарифы

Редактируйте `src/config/products.ts`: `durationDays: null` означает lifetime, цены задаются в копейках. Не доверяйте цене из callback/query — checkout всегда берет продукт и цену с сервера.

## Админка Даши

Укажите Telegram ID администраторов через запятую в `ADMIN_IDS`. Обычный `/start` для них открывает меню админки; `/admin` тоже работает. Обычные пользователи видят прежнее пользовательское меню. Все кнопки админки проверяют `ADMIN_IDS`. Режимы ввода и черновики хранятся в MongoDB и переживают перезапуск.

### Обзор и пользователи

«Обзор» показывает число людей, запустивших бота, новых за сегодня, оплативших, людей без успешной оплаты, активных подписок и подписок, срок которых истекает скоро. «Скоро» означает ближайшие `ADMIN_EXPIRING_DAYS` дней (по умолчанию 3). Раздел «Пользователи» содержит категории, страницы и карточки: Telegram-имя, первый вход, первый и последний источник, полученные материалы, платежи и срок подписки. Считаются только люди, которых видел Telegram-бот; переходы и комментарии в Instagram без передачи данных от SMM-бота неизвестны.

«Не оплатили» означает отсутствие платежа со статусом `succeeded`. «Активная» проверяется по статусу и будущему сроку либо бессрочному доступу. «Закончилась» включает неактивные и истёкшие подписки. «Начали бота» — все сохранённые пользователи.

### Бесплатные материалы

1. Откройте «🎁 Материалы и ссылки» → «Создать материал», пришлите название.
2. В карточке добавьте сообщения в нужном порядке. Поддерживаются текст, фото/видео с подписью, документ/PDF, видеокружок, аудио, голосовое, анимация и стикер. Нажмите «Готово».
3. При необходимости откройте список сообщений: можно заменить сообщение, изменить текст/подпись, заменить медиа с сохранением подписи, удалить после подтверждения и поменять порядок. Название и внутреннюю пометку можно исправить в карточке.
4. «Предпросмотр» отправляет последовательность сообщений и отдельное приглашение в клуб. Текст приглашения и название кнопки можно изменить для каждого материала.
5. Нажмите «Опубликовать», скопируйте ссылку `https://t.me/<bot>?start=m_...` из карточки и передайте её SMM-боту. Каждый материал получает собственный код, поэтому ключевые слова Instagram могут совпадать.

При переходе бот выдаёт актуальную версию материала, сохраняет первый/последний источник и добавляет материал в список полученных без дублей. Повторный переход снова выдаёт материал. После полной выдачи пользователь без активной подписки сразу получает предложение открыть существующий выбор тарифов. Администратор по ссылке тоже получает материал для проверки. Отключённая или неизвестная ссылка с кодом материала сообщает, что материал недоступен. Редактирование опубликованного материала не меняет ссылку. Пустой материал опубликовать нельзя.

Telegram хранит скопированные медиа в исходном сообщении администратора: не удаляйте исходные сообщения с медиа из чата с ботом, иначе предпросмотр и выдача могут перестать работать. Текст сохраняется отдельно. Подпись ограничена Telegram 1024 символами, текст сообщения — 4096 символами; видеокружок не поддерживает подпись, для него замените всё сообщение.

### Рассылки

Откройте «📣 Рассылки», добавьте несколько сообщений по порядку, выберите аудиторию (все или одну из категорий пользователей), исправьте нужное сообщение и посмотрите предпросмотр. Перед отправкой бот покажет аудиторию и число получателей. Отправка начинается только после отдельного подтверждения. Во время работы приходят сообщения о ходе, затем итог с доставленными, ошибками и заблокировавшими бота. Двойное нажатие не запускает отправку повторно. После перезапуска незавершённая рассылка возобновляется с сохранённой позиции. Позиция фиксируется до обращения к Telegram, поэтому при аварии в момент отправки один получатель может быть пропущен, но не получит дубликат; такой случай учитывается как ошибка. Пустую рассылку отправить нельзя.

Отложенные напоминания после материала сейчас не добавлены. Существующие напоминания о подписке продолжают работать.

## Troubleshooting

- `CONFIG ERROR`: заполните перечисленные env-переменные.
- `MongoDB connection failed`: проверьте URI, сеть и разрешенный IP в Atlas.
- `Telegram bot initialization failed`: проверьте `BOT_TOKEN`.
- `Cannot verify club permissions`: проверьте ID супергруппы и права администратора.
- webhook 401: методы хеширования и Пароль №2 в Robokassa не совпадают.
- invite не создается: бот не администратор или не имеет права приглашать.

Health check: `GET /health` → `{ "status": "ok" }`.

## Автоматическое обновление VPS из GitHub

Сервер хранит Git checkout в `/opt/dasha-bot`. Таймер `dasha-bot-deploy.timer` проверяет `main` каждые пять минут. Новая версия устанавливается в отдельную папку, проходит форматирование, lint, typecheck, тесты и сборку. Только после этого PM2 переключается на неё; при неудачном health check предыдущая версия возвращается. Серверный `.env` копируется в новую папку и никогда не берётся из GitHub.

HTTP-сервер по умолчанию слушает только `127.0.0.1`; публичный HTTPS принимает Nginx. Для другого сетевого окружения можно задать `HTTP_HOST` в `.env`.

На сервере: `systemctl status dasha-bot-deploy.timer`, `journalctl -u dasha-bot-deploy.service -n 80`, `git -C /opt/dasha-bot rev-parse --short HEAD`. Публикация новой версии выполняется отправкой проверенного коммита в `main`.

## Предзапись перед открытием

`PRE_REGISTRATION=true` (по умолчанию) скрывает тарифы и создание новых оплат, включая старые кнопки. Материалы по `?start=<код>` выдаются как прежде, после них предлагается «ЖДУ ОТКРЫТИЯ». Нажатие сохраняет дату согласия и источник в пользователе; повторное нажатие не изменяет первую запись. Админка → Пользователи → Предзапись содержит список и карточки ожидающих.

Для открытия установите `PRE_REGISTRATION=false` и перезапустите бота. Существующая Robokassa и обработка платежей сохранены. Админка → Рассылка → Аудитория → Предзапись: добавьте текст и медиа (вместе с подписью или отдельными сообщениями), при необходимости включите кнопку «Вступить», проверьте предпросмотр и подтвердите отправку. Кнопка ведёт к действующим тарифам; пока режим предзаписи включён, она ведёт к записи. Рассылка сама не запускается. Форматирование текста и подписей сохраняется, включая после редактирования.

Instagram должен отправлять ссылку, созданную в разделе «Материалы»; сам бот не читает Instagram Direct. Код ссылки использует допустимые Telegram символы: латинские буквы, цифры, `_` и `-`.

## Запуск с чек-листом

`CHECKLIST_MODE=true` сохраняет прежние ограничения для материалов и меню; на первом экране всё равно показывается новое приветствие без кнопки чек-листа. Для продаж задайте `CHECKLIST_MODE=false`, `PRE_REGISTRATION=false` и `PUBLIC_PAYMENTS_ENABLED=true` в серверном `.env`.
